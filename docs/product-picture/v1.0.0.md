# Finance Agent — Product Picture

## Mission
A private, always-on personal finance companion that helps me **decide, log, and plan** — by understanding my full context and answering "can I afford this?" with real tradeoffs, not just numbers.

## Design principles
1. **Companion, not nanny** — warm, factual, never moralizes
2. **Reduces cognitive load** — replaces my mental math, doesn't add new homework
3. **Honest about uncertainty** — surfaces data gaps and asks rather than guessing silently
4. **Privacy is non-negotiable** — all inference and ledger local; only encrypted backups leave the box
5. **Decision support with tradeoffs** — answers come with consequences, not just yes/no
6. **Low-friction capture** — the easier logging is, the better the data, the smarter the agent

## The four moments it lives in
| Moment | Example | Agent does |
|---|---|---|
| Checkout | "Can I afford this ₹60k laptop?" | Forward simulation, returns: yes / yes-but-tradeoff / no |
| In-the-moment log | "spent 450 on Swiggy" | Parse, categorize, log, silent unless anomaly |
| Check-in | "how am I doing this week?" | Pulse: cash flow, goal progress, anomalies |
| Planning | "can I do Goa in May?" | Forward simulation across all goals + obligations |

## What it knows (data model)
- **Profile**: identity, location (Delhi), salary cadence, tax context
- **Accounts**: balance(s), last reconciled timestamp
- **Income**: single monthly salary (post-TDS), predictable date
- **Fixed obligations**: rent, EMIs, subscriptions, family transfers — each with amount + frequency + due date
- **Goals**: short-term targets, emergency fund, 80C/NPS/ELSS, long-term wealth — each with target + date + current progress
- **Transactions**: full ledger with category, merchant, date, source
- **Tax shadow**: estimated annual liability fenced off, never "spendable"
- **Patterns** (agent-derived over time): weekly shape, category averages, recurring detection, anomaly thresholds

## How "safe to spend" works — forward simulation
Every "can I afford X?" runs the same engine:
1. Project balance day-by-day to the furthest goal deadline (or 6 months, whichever is later)
2. Subtract scheduled outflows: fixed obligations + average variable spend + goal allocations + tax shadow
3. Insert proposed purchase at today
4. Re-check: do all goals still hit on time? Does balance ever cross the emergency-fund floor?
5. Return: **yes** / **yes-but-tradeoff** ("Goa pushes 3 weeks") / **no** ("breaks rent next month")

**Buffer model:** The emergency fund goal IS the floor. Once funded, that money is invisible to safe-to-spend. No separate buffer concept.

## How data flows in
- **Primary**: chat or voice — "spent 500 on Uber"
- **Bulk**: PDF/CSV bank statement → parse, dedupe against logged, queue ambiguous for confirmation
- **Receipts**: photo → OCR for amount + merchant → suggested category
- **Backfill**: if I haven't logged in N days, agent nudges me to walk through the gap
- **Out of scope (v1)**: Account Aggregator / bank API auto-pull

## Channels
- **Signal** (primary, on-the-go) — chat with the bot via your phone or desktop Signal client. E2E encrypted by default; aligns with the privacy principle. (Switched from Telegram in May 2026 during security planning — see [Security v1.0.0](../security/v1.0.0.md).)
- **Web UI at home** — local-only chat surface on `127.0.0.1` for longer laptop sessions. No remote web access in v1.

## Categorization
Sensible defaults (food, transport, groceries, utilities, entertainment, etc.) but **learns from my corrections over time**. When I re-categorize something, the agent updates its rules. Categories evolve with me.

## Edge cases handled in v1
- **Joint / split** — "₹1200 dinner, splitting 3 ways" → tracks who owes me, my share only counts as spend
- **Reimbursable** — work expense paid personally → "pending reimbursement", excluded from safe-to-spend until reconciled
- **Cash withdrawals** — ATM ₹5k → "cash float", nudges me to attribute later
- **Refunds / returns** — reverses original or credits as income

## Anomalies it watches for
- Spending spikes by category ("Swiggy 4× this week vs usual 1-2")
- New recurring charge detected ("CULT.FIT ₹499 — new subscription?")
- Missed expected recurring ("Netflix usually charges by the 5th — nothing yet")
- Unusually large single transaction (>2× typical merchant/category, or absolute threshold)

## Briefings
- **Morning brief (daily)** — yesterday's spend + today's known outflows + anomalies/nudges when relevant
- **Sunday weekly review** — week recap, goal progress, **+ forward look at next 30 days** (upcoming bills, deadlines, projected landing)

## Time horizons (agent picks per question)
- Short (7-30 days) — cash flow
- Medium (this month/quarter) — variable spend pacing, goal tracking
- Long (annual) — tax planning, big-picture

## Tone
Warm but factual. Conversational, direct, no condescension. *"Yeah you can swing it — just FYI that eats into your Goa buffer by ~₹6k."*

## Boundaries — what the agent does NOT do
- No investment advice / stock picking (tracks 80C amounts toward limits, doesn't recommend instruments)
- No moralizing about spending
- No tax filing or legal advice (estimates + deadline reminders only)
- No external actions without confirmation (never auto-pays, transfers, places trades, contacts anyone)

## Privacy
- All inference on the Asus (local Ollama)
- Bank statements parsed locally — never leave the box
- Only encrypted backups go to cloud (R2/S3)

## Explicitly NOT in v1 (deferred)
- Account Aggregator / bank API auto-pull
- Multi-account complexity beyond basic tracking
- Investment portfolio tracking (beyond 80C limit tracking)
- Insurance management
- Multi-user (family)

## Open questions for next phase (implementation planning)
- Goal setup mechanics (fields, deadlines, recurring contribution rules)
- How the categorization-correction memory actually works
- Subscription detection rules (frequency + amount tolerance)
- Forward simulation parameters (averaging window, goal weighting when balance is tight)
- How the agent handles salary changes (raise, job change, gap)
